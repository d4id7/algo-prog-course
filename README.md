# algo-prog-course
ПР1. Ответы на контрольные вопросы:
1. В интерпретируемом языке мы сможем найти ошибку только тогда, когда интерпритатор дойдёт до неё во время выполнения программы. В компилируемом языке пррграмма даже не запуститься, если в одной из строчек кода будет ошибка (даже если она никогда не выполниться).

2. Первый шаг - она собирает программу (компилирует код, переводя его на машинный язык), второй шаг - запускает программу

3. Папки /bin и /obj хранят результат выполнения программы на конкретном устройстве, а не исходный код

4. git commit сохраняет снимок (коммит) с сообщением, git push отправляет этот снимок в удалённый репозиторий

5. + склеивает между собой строки, но с большии количеством переменных код становиться нечитаемым, а $"…" делает тоже самое, оставляя при этом код понятным

6. При деление int на int результат тоже будет int, а дробная часть отбросить. Чтобы это исправить нужно хотя бы одну переменную перевести в double

7. const делает переменную неизменяемой в будущем, т. е. при попытке внести в неё значение в последующих строчках кода компиллятор будет выдовать ошибку при запуске программы. const можно использовать для неизменных значений, например для формул: const double g = 9.8;

8. top-level statements позволяет писать код, без написания class Program {static void Main ()}, компилятор сам достраивает эту часть кода

1. В отличие от decimal, double хранит число в двоичном коде, что в дробных значениях может вызывать искажение

2. В таком случае значение сброситься до минимума ("обернётся" по кругу)

3. var присваивает тип данных переменной раз и навсегда во время компиляции

4. string

5. int.Parse выдаёт ошибку, а int.TryParse возвращает значение false (при этом переменная, объявленная внутри int.TryParse, возвращает значение 0)

6. false означает, что в int.TryParse передали не число, при этом в переменную, переданную через out, попадёт значение 0

7. TryParse можно использоват, когда мы не знаем, что может ввести пользователь (т. е. почти всегда), чтобы программа не "упала"
